# Совместимость

<!-- l10n: source=reference/compatibility.md source-sha256=9f3a7654d57410845e20c92eccc746868cbac665b4d937581f16c3818d7b7b88 -->
> Перевод [исходной страницы на английском языке](../../../reference/compatibility.md) для OmsiLaunch 0.1.0-beta4. Нормативной является английская страница: при расхождениях приоритет имеют английская страница и код.

OmsiLaunch работает с установленной **OMSI 2**. Он не требует какого-то одного файла `Omsi.exe`: каждое нативное допущение, которое он делает внутри OMSI (функция, место патча, класс, слот VMT, глобальная переменная, смещение поля), определяется и проверяется отдельно, в процессе, перед использованием, а возможность доступна, только если проверены все её допущения. На этой странице указано, что означает «установлена OMSI 2», как идентифицируются сборки, как определяются возможности и каковы требования к операционной системе и среде выполнения. Источники: `src/OmsiLaunch.Builds.Omsi23004/OmsiBuildDetection.cs`, `src/OmsiLaunch.Builds.Omsi23004/NativeTargetCatalog.cs`, `src/OmsiLaunch.NativeResolution/`, `src/OmsiLaunch.Plugin/PluginNativeTargets.cs`, `src/OmsiLaunch.Core/SessionPlanner.cs`, `src/OmsiLaunch.Process/RuntimePlatform.cs`.

<a id="requirement-omsi-2-installed"></a>
## Требование: установлена OMSI 2

План отклоняется с `OL_E_UNSUPPORTED_BUILD`, только если установка не является установкой OMSI 2:

| Проверка | Отклоняется, когда |
| --- | --- |
| `Omsi.exe` | отсутствует в корневом каталоге установки |
| Образ | не является 32-разрядным образом PE x86 |
| Версия | в ресурсе версии нет версии OMSI 2 (2.x) |
| Установка | в корневом каталоге нет каталога `maps\` или `Vehicles\` |

SHA-256, размер и точная версия исполняемого файла **не** являются критериями совместимости. Они записываются как диагностика (`omsi.build.detected`, `OmsiLaunch.exe profiles`) и служат подтверждением.

<a id="build-identity-and-capability-resolution"></a>
## Идентичность сборки и определение возможностей

| Понятие | Значение |
| --- | --- |
| Идентичность кода | SHA-256 основной секции кода исполняемого файла. Известная идентичность выбирает известную раскладку как быстрый путь. Варианты, отличающиеся только заголовками (например, копия с Large Address Aware), имеют общую идентичность кода. |
| Известная раскладка | `Omsi23004`: OMSI 2.3.004 (версия файла 2.2.032), идентичность кода `13ec110abdccc09d6d85875a017d5e75e45514283d5a4558f49a7c282dfdc028`. Все проверки в runtime со [страницы статуса](../status/runtime-validation-status.md) выполнены на этой раскладке. |
| Нативная цель | Одно допущение нативной границы, объявленное в каталоге сборки вместе с его проверкой (guard). |
| Возможность | Группа целей, например `world.new-map` или `time.read`. Доступна, только если каждая цель определена **и** проверена. |

Как цель определяется в плагине до того, как OmsiLaunch что-либо патчит:

1. **Известная идентичность:** сначала пробуется эталонный адрес известной раскладки, и он по-прежнему должен проходить проверку (guard) цели.
2. **Иначе, или если проверка не пройдена**, пробуются стратегии, не зависящие от сборки:
   - имя класса Delphi RTTI (проверяется `vmtSelfPtr`);
   - опубликованные методы, поля и свойства класса (таблицы RTTI);
   - слот VMT, содержащий определённый метод;
   - маскированная сигнатура кода, которая должна совпасть ровно один раз (операнды, зависящие от раскладки, — подстановочные символы), с захватом адреса, глобальной переменной (напрямую или через её ячейку-указатель) или смещения поля внутри метода собственного класса этого поля.
3. **Ничто не совпадает однозначно и не проходит проверку:** цель остаётся неопределённой. **Резервного перехода на фиксированный адрес нет.**

Проверки (guards): маскированные входные байты для функций и мест патча, адрес назначения вызова для пропатченного вызова, `vmtSelfPtr` и имя класса RTTI для классов, удерживаемый метод для слотов VMT и записываемая секция данных для глобальных переменных. Раскладки объектов, которые читают runtime-читатели (записи транспортного средства, Human, погоды, расписания и т. д.), пока не имеют структурной проверки, не зависящей от сборки. Они проверяются только для известной идентичности кода, поэтому возможности, которые их читают, недоступны на сборке с неизвестной идентичностью.

На известной раскладке определяются все возможности. На сборке с неизвестной идентичностью могут быть доступны возможности, цели которых определяются перечисленными выше стратегиями (headless-запуск, NEW_MAP, сохранённые ситуации, подавление интернет-текстур, чтение и установка времени, D3D), причём каждая проверяется отдельно; чтения, зависящие от раскладки, недоступны.

<a id="where-compatibility-is-decided"></a>
## Где решается вопрос совместимости

| Этап | Что происходит |
| --- | --- |
| Планирование (`PlanSessionAsync`, `/plan`) | Проверка OMSI 2 (`omsi.omsi2`, иначе `OL_E_UNSUPPORTED_BUILD`). Образ файла определяется как **прогноз**: необходимые нативные возможности несут `RESOLVED_KNOWN_LAYOUT`, `STATICALLY_RESOLVED` или `PENDING_IN_PROCESS_RESOLUTION` с предупреждением `OL_W_CAPABILITY_PENDING`. Неизвестная идентичность кода добавляет предупреждение `OL_W_BUILD_UNRECOGNIZED`. Предупреждения не делают план неисполнимым. |
| Запуск (`StartSessionAsync`) | Спецификация планируется повторно; план, который перестал быть исполнимым, отклоняется с `OL_E_PLAN_NOT_RUNNABLE`. |
| В процессе (запуск плагина) | Загруженный образ определяется (авторитетно; исполняемый файл с защитой DRM может отличаться от своего файла). Отчёт отправляется как телеметрия `native.capabilities`. Если `boot.headless-start` и возможность режима мира (`world.new-map` или `world.saved-situation`) недоступны, сеанс завершается с `OL_E_CAPABILITY_UNRESOLVED` до установки любого хука, а файлы восстанавливаются. Если они доступны, но живая форма Start не в ожидаемом состоянии (например, её пропатчил другой плагин), сеанс завершается с `OL_E_BUILD_VALIDATION_FAILED`. |
| Runtime-операции | Операция, возможность которой недоступна, отклоняется с `OL_E_CAPABILITY_UNRESOLVED` (`Data["capability"]`) без обращения к памяти OMSI. |

`OmsiLaunch.exe profiles --json` сообщает об установке (`is_omsi2`, `build_id`, `identity`, хеши файла и кода, `file_variant`), известных раскладках и возможностях, предсказанных по файлу.

<a id="operating-system-and-architecture"></a>
## Операционная система и архитектура

`CurrentWindowsX64Platform.Detect` вычисляет `RuntimePlatformInfo`. Текущая платформа поддерживается, только если выполняются все следующие условия:

| Требование | Проверка | Ошибка при нарушении |
| --- | --- | --- |
| Windows | `OperatingSystem.IsWindows()` | `OL_E_UNSUPPORTED_OPERATING_SYSTEM` |
| Windows 10 или новее | `Environment.OSVersion.Version.Major >= 10` (Windows 10, Windows 11, Server 2016+) | `OL_E_PLATFORM_CAPABILITY_MISSING` |
| 64-разрядная Windows и 64-разрядный процесс хоста | `OSArchitecture == X64` и `ProcessArchitecture == X64` | `OL_E_UNSUPPORTED_OS_ARCHITECTURE` |
| Установка, доступная для записи | Корневой каталог существует, не доступен только для чтения и содержит `plugins\` | `OL_E_INSTALLATION_NOT_WRITABLE` |

`RuntimePlatformInfo` также сообщает `OmsiArchitecture` и `PluginArchitecture` как `X86` (OMSI — 32-разрядный процесс; замыкание плагина (набор его файлов) имеет архитектуру x86 и работает под WOW64), `LegacyPlatform=false` и `Wow64Available`. Windows на ARM64 не поддерживается даже там, где есть эмуляция x64, потому что процесс хоста сам должен быть x64.

## Требования к .NET

| Компонент | Среда выполнения | Примечания |
| --- | --- | --- |
| Контроллер (`OmsiLaunch.exe`, `OmsiLaunchW.exe` -> `OmsiLaunch.Controller.dll`) | .NET 6, x64 | Нативный загрузчик (bootstrapper) находит среду выполнения через `hostfxr` с помощью входящего в пакет `nethost.dll`. Об отсутствии среды выполнения сообщает shim (коды выхода 100-106; см. [CLI](cli.md) и [коды выхода](exit-codes.md)). |
| Замыкание плагина (`plugins\OmsiLaunch.Plugin.dll` через `OmsiLaunch.PluginNE.dll`) | .NET 6, **x86** (`net6.0-windows`, `win-x86`), размещается DNNE 2.0.6 внутри `Omsi.exe` | Требует, чтобы на компьютере была установлена среда выполнения .NET 6 Desktop/Core x86; одной 64-разрядной среды выполнения для плагина недостаточно. |
| Нативный мост (`plugins\OmsiLaunch.Native.x86.dll`) | нативный x86 | Загружается только из `plugins\` (см. [постоянный плагин](../concepts/permanent-plugin.md)). Не содержит ни одного адреса OMSI: проверенную таблицу целей он получает от плагина. |

<a id="legacy-platforms"></a>
## Устаревшие платформы

Windows 7, Windows 8.x, Windows XP и другие системы NT 6 и более ранние находятся за пределами текущей границы поддержки. `RuntimePlatformInfo.LegacyPlatform` всегда равен `false`, и адаптера для устаревших платформ нет; поле и точка расширения `IPluginNativeServices` существуют только для того, чтобы в будущем можно было добавить такой адаптер без изменения публичного API (см. `docs/adr/ADR-0010-Legacy-Portability-Boundary.md`). Ничто в этом выпуске на таких системах не работает.

<a id="steam-and-large-address-aware-notes"></a>
## Примечания о Steam и Large Address Aware

- Копия с Large Address Aware, отличающаяся от оригинала только заголовками, имеет ту же идентичность кода и использует ту же известную раскладку.
- Исполняемый файл Steam на диске защищён DRM, поэтому его файл может отличаться от загруженного образа: план может сообщить `OL_W_CAPABILITY_PENDING`, а решает определение в процессе. Сеанс с подлинным исполняемым файлом Steam не проверялся в runtime (см.
- Steam запускает OMSI самостоятельно; сеанс должен запускаться через `OmsiLaunch.exe`, чтобы существовал handoff. При запуске из Steam постоянный плагин остаётся неактивным (нет handoff, нет хуков).
